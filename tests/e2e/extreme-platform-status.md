## Decisiones técnicas y límites

- ATE determinista permanece separado de IA: `--scenarios` no construye modelo; generación `--request` cachea el plan validado, y el resultado de navegador no se cachea. No invocar Gemini fue intencional en este corte.
- La protección existente no se debilitará para satisfacer misiones. La app bajo prueba usa identidad y configuración sintéticas; Admin SDK se limita a preparar/restablecer UID reservados en Emulator, mientras las acciones funcionales y permisos se verifican desde UI/SDK cliente.
- El almacenamiento de cuota es agregado, no persiste prompts/secrets; no se ha validado coordinación atómica entre procesos separados que compartan el archivo de uso. El cap de coste se calcula con tokens estimados antes de llamada y metadatos reales después; una respuesta podría superar el cap si la salida excede la estimación. La reserva estimada sí se comparte entre llamadas concurrentes dentro del mismo gestor.
- La configuración `.env` de Agentic Test Explorer no se leyó ni se copiará a reportes/artefactos.

## Verificación ejecutada en este corte

- Agentic Test Explorer: `PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -m unittest discover -s tests` → **140 tests, OK, 5 omitidos**; test focal de presupuesto **14/14**. Incluye expansión/ejecución de 1.000 pasos, historial atrás/adelante/recarga, guard Emulator fail-closed negativo, Retry-After, clasificación de timeout/429/503 y límites de tokens/coste concurrente; sin proveedor. Un primer intento en sandbox falló al iniciar Chromium por `MachPortRendezvousServer ... Permission denied`; el rerun aprobado fuera del sandbox terminó en éxito. No se hizo petición a proveedor.
- TAI perfiles deterministas con Emulator: QUICK **2/2**; INTENSIVE **4/4**; EXTREME **6/6**. Incluyen historial/recarga y repeticiones 10+50+100+500+997 clics; escenario límite **1.000 pasos**. En los tres: `llm_calls=0`, proyecto `demo-tai-auth`, guard de red activo, no se registraron destinos bloqueados. Evidencias reproducibles en `test-results-explorer/run-cLq3rk`, `run-gtUqXm` y `run-CSDBL0` (configuración/run.json/Action Tape). Las ejecuciones calibratorias detectaron primero un selector de nav inexistente y después que 1.000 clics excedían el límite total al sumar navegación/aserciones. La misión se corrigió a selector real observado en DOM y 997 clics (1.000 pasos incluyendo soporte); la versión final pasó los tres perfiles.
- Estos perfiles son stress de navegación autenticada y aserciones de destino/health. No prueban que los datos de estudio resistan doble envío, persistencia de tests, concurrencia de pestañas ni consistencia entre módulos.
- Trabajo TAI precedente: Auth Emulator supertest **7/7**; misión ATE owner smoke **48 pasos / 16 rutas**; E2E TAI global **186 aprobadas / 66 fallidas / 16 omitidas**, 64 discrepancias visuales heredadas y 2 timeouts WebKit. Se reprodujeron los dos timeouts WebKit claro/oscuro con test aislado. Diagnóstico confirma `main.planning-page` oculto sin ancestro oculto, clase `.invisible`, atributo `hidden`, estilo inline ni regla CSS coincidente identificada; causalidad sigue pendiente (UX-007). Estos resultados son evidencia separada.
- TAI Firebase prod y datos reales: no utilizados en este corte.
- UX-007 revalidado: en WebKit claro/oscuro `main.planning-page` es `visibility:hidden` inmediatamente tras abrir la ruta, antes de interactuar. Ancestros visibles, sin `hidden`, `inert`, clase `.invisible` o regla CSS coincidente identificada. `selectOption` sigue fallando al timeout original de 30 s. UX-010 corregido; E2E móvil 1/1 Chromium + 1/1 WebKit. `npm run check`: 958 aprobadas/27 omitidas. `routes.spec.ts` con snapshots candidatas: **86/86**. `npm run test:e2e:ci`: baseline 70/70, candidata 188/66/16; 64 capturas son drift esperado frente al baseline antiguo y 2 timeouts corresponden a UX-007.
